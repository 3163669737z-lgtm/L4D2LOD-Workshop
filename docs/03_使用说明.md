# 远景工坊 · L4D2 自动 LOD 工具 · 使用说明

> 给 L4D2 模型工程自动做多级 LOD：用 Blender 减面，再把 `$lod` 写回 QC。
> 双击 `L4D2LOD远景工坊.exe` 就能用，**不需要装 Python，也不需要命令行**。
>
> 版本：7.0.0（Windows 10 1903+ / Windows 11，自带 .NET Framework 4.8，无需安装任何运行库）
> 需要：Blender 4.0 / 4.1 / 4.2（必需）；nekomdl.exe（可选，只有开「生成后试编译」才用）

---

## 0. 五分钟上手（第一次用先看这里）

1. **准备**：确认 Blender 能正常打开（4.0 / 4.1 / 4.2 都行）；把 `L4D2LOD远景工坊.exe` 放到一个有写权限的位置
   （桌面、D 盘工程目录都可以，别放在 `C:\Program Files` 下）。
2. **指定引擎**：菜单 ☰ →「打开设置…」→「引擎」页 → 点「自动查找」或「浏览…」选 `blender.exe`，
   状态行出现版本号（如 `4.1.1`）即可；只做 LOD 不试编译的话，编译器不用设置。
3. **加工程**：把一个工程文件夹拖进窗口（或点「+ 导入」选工程文件夹）。加入后会自动只读扫描，
   队列行显示 `N QC · M 模型` 或跳过原因。
4. **预览**：点「扫描预览」，确认「作业计划」里"会处理哪些 QC、跳过哪些、为什么"。没问题就点「返回队列」。
5. **生成**：点「开始生成」（`F5`），确认「确认修改 QC」；等 Blender 跑完，看 HUD/Toasts，点「报告」查看结果。
6. **编译**：回到你自己的工程目录，双击原来的 `批量编译.bat`（工具不接管编译）。
7. **不放心就还原**：改过的 QC 旁有 `xxx.qc.lodbak`（第一次修改前的原件），改回 `.qc` 即可。

> 第一次建议先用一个**工程副本**试跑；或者先看 `docs/04_验收报告.md` 里的已知限制。
> 工具默认 4 级 LOD（10/15/25/50 HU，99.7%→16.1%），与官方角色参数一致；不确定就用默认。

## 1. 它是什么

L4D2 的模型靠 QC 脚本里的 `$lod` 块按"距离"切换不同精度的模型。远景工坊做三件事：

1. **找**：从你的工程目录里找出真正会被编译的 QC（优先读你已有的 `批量编译.bat`），展开 `$include` 链，收集所有模型引用；
2. **做**：调 Blender 把每个模型减面成若干级（`*_lod1.glb`、`*_lod2.glb`…），默认 4 级；
3. **写**：把对应距离的 `$lod { replacemodel … }` 幂等写回 QC，**改写前自动备份**，可以随时还原。

做完之后，**照旧双击你自己的 `批量编译.bat` 就行**——工具不接管编译，只把 LOD 文件和 QC 准备好。

它会做的事：只读扫描、生成 LOD 文件、给 QC 加 LOD 块（或生成 `_LOD.qc`/`_LOD合集.qc`）、备份、写报告与日志。
它**不会**做的事：不修改 `.bat`、材质、贴图、模型源文件；不替你执行编译；不联网、不更新、不收集数据。

## 2. 第一次使用

### 2.1 权限问题（最常见）

Windows 有一个"完整性级别"机制：从网上下载的 exe 可能被标成 **Low**，这种程序**写不进任何普通文件夹**，
表现为「扫描正常、一开始生成就全失败」。

先看主窗口顶栏右侧的权限读数（只读指示，点不开）：

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 普通权限（弱点） | 正常方式双击启动 | 一般够用；若杀软拦截写文件，见下 |
| 管理员（绿点） | 以管理员身份运行 | 正常 |
| **低完整性（红点）** | 哪里都写不进去 | 把 exe 复制到桌面或其它盘再运行；或右键 exe → 属性 → 勾「解除锁定」；或用管理员执行一次 `icacls "<exe路径>" /setintegritylevel Medium` |

另外，火绒等安全软件可能拦截普通权限程序写文件：把本工具加入信任区即可（**保留拖放功能**），或者右键「以管理员身份运行」。
工具也能从菜单「以管理员身份重启」（当前不是管理员时可见），会用 `runas` 重新启动并把队列前 8 项一起带过去。

> 管理员运行时**收不到资源管理器拖放**（Windows 的 UIPI 限制），请用「导入」按钮。

### 2.2 指定 Blender（第一次）

点右上「菜单」（☰）→「打开设置…」→「引擎」页：

- 程序通常会自动找到 Blender（注册表 / 常见安装目录 / D: 盘 / Steam 库，新版本优先）。
- 找不到就点「浏览…」选 `blender.exe`；状态行会显示检测到的版本（如 `4.1.1`），`Blender 4.1.1` 这样的版本号也会出现在顶栏和「关于」里。
- 编译器（`nekomdl.exe`）是可选的：只有打开「生成后试编译」才需要。一般与 `studiomdl.exe` 放在一起
  （`...\steamapps\common\Left 4 Dead 2\bin\nekomdl.exe`）。

## 5. 添加任务

三种方式，效果一样（顶部的工具行不再放导入按钮，只留筛选页签和搜索框）：

1. 队列为空时，中间有两个按钮：
   - **「导入文件夹」**：选择工程文件夹；
   - **「导入文件」**：一次多选 QC / GLB / SMD 文件（统一入口，不再按类型分菜单）。
   队列里已有任务时，用下面的右键/菜单/拖放继续导入。
2. 把文件或文件夹**直接拖进窗口**（整个窗口都能接收，拖入时出现拖放高亮：多文件显示「松开加入 N 项」，
   单文件/其它情况显示支持的类型提示）。
3. 队列**右键菜单**或右上 **☰ 菜单**（最上面两项）→ 导入文件夹 / 导入文件（QC / GLB / SMD）。

> 快捷键：`Ctrl+O` 导入文件、`Ctrl+Shift+O` 导入文件夹。

**关于「导入文件夹」的选择窗口**：和「导入文件」用的是**同一类系统资源管理器窗口**
（标题「选择工程文件夹」、底部按钮「选择文件夹 / 取消」）——地址栏可以直接输入或 `Ctrl+V` 粘贴路径，
左侧有桌面/文档/下载等导航，右上角有搜索；不再是老式树形对话框，也不是程序自绘窗口。

| 拖入的东西 | 工具怎么处理 |
|---|---|
| 工程文件夹 | 优先解析目录里 `*.bat` 中 `nekomdl` 命令行里的 QC；没有可用 bat 时找含 `$modelname` 且没被其它 QC `$include` 的 QC；如果整个文件夹没有 QC，就为散落的 `.glb/.smd` 各建一个包装 QC（搜索深度 3 层，跳过 `_LOD*` 目录与已有 `_lodN` 产物） |
| `.qc` | 直接作为根 QC 处理（会展开它的 `$include` 链） |
| `.glb` / `.smd` | 在模型同目录建 `自动LOD_<模型名>.qc`（已存在就沿用，**绝不覆盖**），再按正常 QC 处理 |

其他类型文件会被忽略（提示"无法识别"）。同一个任务重复加入只保留一条。
加入后会**立刻自动扫描**（只读，不改任何文件），每行显示规模（QC 数 / 模型数）或跳过原因。

## 6. 作业队列

### 6.1 筛选、搜索与选择

- 页签：`全部 / 未完成 / 完成 / 异常 / 跳过`，括号里的数字是实时计数。
- 搜索框：按名称或路径过滤（`Ctrl+F` 聚焦，`Esc` 清空）；有文字时右侧出现 × 清除按钮。
- 无匹配时显示「没有匹配的任务」和「清除筛选与搜索」按钮。
- 搜索框进入输入状态（插入符闪烁）后，点窗口里除搜索框以外的**任意位置**都会结束输入状态（收起插入符），不需要先按 Esc。
- 多选：`Ctrl+点击` 或 `Shift+点击`；`Ctrl+A` 全选。
- 行内按钮：在资源管理器中显示、从列表移除（**不删文件**）。行 hover 时按钮才明显。

### 6.2 队列表列

| 列 | 内容 |
|---|---|
| 序号 | 01、02…（拖动/排序后重排） |
| 类型 | 工程文件夹 / QC / GLB / SMD（图标 + 文字） |
| 名称 / 路径 | 主行名称，副行父路径（等宽字体，超长省略） |
| 规模 | 扫描后显示 `N QC · M 模型`；未扫描显示「…」/「扫描中…」；跳过的项显示原因 |
| 状态 | 待处理 / 扫描中 / 处理中 / 完成 / 部分完成 / 失败 / 跳过 / 已停止 |
| 操作 | 显示到资源管理器、移除 |

鼠标悬停行可看提示（类型、路径、规模、上次结果与错误摘要）；双击或 `Enter` 打开详情对话框
（按钮：在资源管理器中显示 / 关闭），详情会列出每个 QC 与其模型条目的处理判断（✓ 生成 LOD、✘ 缺失、带 innode 跳过等）。

### 6.3 右键菜单

导入文件夹 / 导入文件（QC / GLB / SMD）/ 查看详情 / 在资源管理器中显示 / 移到最前 / 移到最后 / 移除选中项 / 清空列表…
（「清空列表」会确认，且只移出列表、不删文件。）

### 6.4 页脚

`上次运行：刚刚 · 3 完成 · 1 失败` + 右侧「查看报告 ›」（没有报告时禁用）。运行中队列锁定，不能添加/移除/调整顺序。

## 7. 扫描预览与作业计划

点 **「扫描预览」**（HUD 左侧，只读）：工具会展开任务、解析 QC、全局去重、统计面数，然后打开**「作业计划」**视图：

- 每个根 QC 会**生成**还是**跳过**（以及原因）；
- 每个 QC 的模型（前 3 个 + 数量）与任务数；
- 摘要两行：`将处理 N 个 QC · M 个模型 · K 个减面任务` 与 `跳过 X · 错误 Y · 计划生成于 HH:mm:ss`。

看完可以：

- **返回队列**：不动任何文件；
- **按此计划开始生成**：直接按预览时的参数和计划运行（预览后改了参数也不会影响这一份计划）。

> 扫描预览**不写任何文件、不启动 Blender**。真正写入发生在「开始生成」之后。
> 没有可处理项时会弹「没有可处理的 QC」，展开日志能看到每项的原因。

## 8. LOD 方案

### 8.1 预设

预设库里是 8 个内置预设（按模型类型选）：

| 预设 | 级数（LOD0 之外） | 距离（HU） | 保留比例 |
|---|---|---|---|
| 角色·标准（5级） | 4 | 10/15/25/50 | 99.7% / 65.3% / 34.0% / 16.1% |
| 角色·温和（5级） | 4 | 10/15/25/50 | 85% / 65% / 45% / 30% |
| 角色·精简（3级） | 3 | 15/30/60 | 70% / 45% / 25% |
| 道具·标准（2级） | 2 | 30/70 | 55% / 30% |
| 极保守（2级） | 2 | 40/80 | 85% / 65% |
| 角色·性能（6级） | 6 | 10/15/25/50/100/200 | 99.7/85/65/45/25/12% |
| 角色·极致（8级） | 8 | 10/15/25/40/60/90/130/180 | 99.7/92/78/62/46/32/18/10% |
| 载具·大件（3级） | 3 | 30/70/150 | 70% / 45% / 20% |

- 距离单位是 **HU（游戏单位，1 HU ≈ 1.9 厘米）**。官方角色的标准就是 10/15/25/50。
- 预设是**参数模板**，只影响本次/下次生成的 `$lod` 参数，不会改写其它已存在内容。
- 下拉里是 8 个内置预设；设置文件里已有的「我的预设」（例如从旧版导入的）也会一起列出，选中即应用。
- 改了任意数字后，「恢复」按钮变为可用，可回到当前预设的原始参数（顶部不再显示「已修改」徽标）。
- 保存/删除「我的预设」：右上角 ☰ 菜单里有「保存当前参数为我的预设…」「删除当前我的预设…」；保存后出现在下拉列表底部，选中即应用；删除只影响「我的预设」，内置预设删不掉。
- 需要固定一套参数时，点 ☰ →「保存当前参数为我的预设…」，以后从下拉里直接选。

### 8.2 级别表（数值边输入边生效）

LOD 参数就是一张表：每一级一行，**行高固定 40**（第九轮按反馈恢复）。
级别按实际数量排列，4–7 级时下方正常留空，到 8 级也不会把行拉高或强行铺满。
「距离 HU」和「比例 %」两个数字框**输入即生效，不需要按回车**；失焦或回车会把格式整理成规范写法。

| 列 | 说明 |
|---|---|
| `01` `02` … | 第几级 LOD（LOD0 是原模型，不在这里） |
| 距离 HU | 进入这一级的切换距离；必须一级比一级远（单位 HU，1 HU ≈ 1.9 厘米） |
| 保留比例 | 比例条：拖动可改这一级的保留百分比（0.1% 步进，拖动时右侧数字实时更新）；键盘选中后用 `←`/`→` ±0.5%，`Shift` ±5% |
| 比例 % | 精确数字，可直接输入（0.1–100，如 65.3） |
| × | 删除这一级（至少保留 1 级） |

- 级别表带外框和列分隔线，表头与每格内容都居中；表格下方是一条整宽的「添加一级」按钮（文字居中、带外框），到 8 级自动隐藏。
- 顶部不再显示规格摘要、红字校验提示和「已修改」角标（按反馈移除）；改动参数后「恢复」按钮变为可用。
- **距离自动保持递增**：某一级输入的距离不大于上一级时，会立即按"上一级 + 1"生效（例：第 7 级 130，第 8 级输入 50 → 生效为 131）；
  改大前面的级别时，后面所有级别会依次被顶高。
- **比例自动保持递减**：某一级输入的比例不小于上一级时，会立即按"上一级 - 1 个百分点"生效（例：上一级 18%，本级输入 20% → 生效为 17%）；
  改小前面的级别时，后面所有级别会依次被压低。
- **比例条上限跟着上一级走**：每级拉条最多只能拉到"上一级 - 1 个百分点"，超过会停在上限位置。
- 参数不合法时「开始生成」按钮不可用（旧版的红字原因提示已移除）；鼠标悬停在禁用按钮上会显示具体原因。
- 输入非法内容（空、字母、超范围）不会写坏方案：范围外的值会被夹到合法区间（距离 1–10000 HU，比例 0.1–100%），
  失焦后会整理成规范数字。
- 距离/比例输入框点击进入输入状态后，点它所在格子以外的任意位置都会结束输入状态（正常失焦并整理格式）。

### 8.3 写入方式

| 方式 | 对 QC 做什么 | 产物 |
|---|---|---|
| **原 QC**（默认） | 在每个 QC 末尾追加一个带工具标记的 `$lod` 块；重复运行只替换不叠加 | QC 文件本身 |
| **独立 _LOD.qc** | 每个 QC 旁生成 `xxx_LOD.qc`，原 QC 只多一个工具块（里面是一行 `$include "xxx_LOD.qc"`） | `xxx_LOD.qc` + 原 QC 的 include 块 |
| **仅合集** | 一个 QC 都不改，只在工程根输出 `_LOD合集.qc`（不能直接编译，仅供查看/手工粘贴） | `_LOD合集.qc` |

三种方式改 QC 前都会先备份（默认 `xxx.qc.lodbak`，可在「设置 → 常规」改备份位置或关闭备份）。
独立模式的文件编码/换行沿用原 QC；合集文件是 UTF-8（带 BOM）。
分段控件铺满整行；鼠标悬停在上面可以看到当前方式的文字说明。

## 9. 运行

### 9.1 开始前检查

点 **「开始生成」**（`F5`）时，工具会按顺序检查：

1. 队列非空、LOD 参数合法；
2. 没有 Blender → 弹「还没有指定 Blender」，可点「打开设置」；
3. 开了「生成后试编译」但没设编译器 → 弹「开启了「生成后试编译」，但没有指定编译器」；
4. 任务所在目录不可写 → 弹「有目录无法写入」，可选择「仍然开始」；
5. **写入方式不是「仅合集」时**，弹「确认修改 QC」，说明将写入的内容、是否覆盖手写 `$lod`、备份位置；
   关闭备份时主按钮是危险色并明确提示"本次不会生成 .lodbak，改完无法一键还原"。

确认后开始。按钮变成红色 **「停止」**。

### 9.2 运行中

- 队列锁定（不能加任务、不能改顺序、不能移除）；LOD 参数锁定；
- HUD：分段进度条 + `正在生成 3/8 · 已用 0:42 · 剩余约 2 分钟`（前 2 个任务后才有 ETA）；
  大数字显示"已完成的减面任务数 / 个减面任务"；结束后显示"QC 已写入"；
- 日志实时滚动；如果往上翻，右下角出现「N 条新日志」，点一下回到底部；
- Blender 进度行会显示每个任务的面数与结果；多个 Blender 进程并行时会有 `[并行 w/n]` 前缀。

### 9.3 停止

点 **「停止」** 或按 `Esc`，先弹确认「停止处理 / 会立刻结束所有 Blender 进程…」（主按钮「停止」、次按钮「继续处理」）。
确认后：所有 Blender 立即被杀，HUD 进入「正在停止…」；**已经生成的 LOD 文件保留，但本次不会再修改 QC**；
已注入完成的 QC 保留修改，剩余 QC 原样未动。报告照样会生成。

关闭窗口时如果还在运行，会弹「还在运行 / 停止并关闭 / 继续运行」，确认后同样先结束进程再退出。

### 9.4 跑完

- 右下 Toast 显示结果（完成 / 有失败 / 部分完成 / 已停止）；
- HUD 状态与副行：`全部完成`、`有失败项`、`部分完成`、`已停止`，副行是统计摘要
  （写入 N 个 QC · M 个模型 · 减面 a/b · 试编译 x/y · 原始面数 → 末级面数 · 用时）；
- 有失败或部分完成时弹出汇总对话框，可直接「打开报告」；
- 队列页脚更新「上次运行：刚刚 · N 完成 · N 失败 · 查看报告 ›」；HUD 出现「报告」「目录」按钮；
- 每行的状态与"上次运行"详情会更新（悬停/双击可看）。

### 9.5 结果状态

| 状态 | 含义 |
|---|---|
| 待处理 | 还没运行 |
| 扫描中 / 处理中 | 正在扫描 / 正在运行 |
| 完成 | 该任务下所有 QC 都成功写入（或全部合理跳过且无错误时…见下） |
| 部分完成 | 有的 QC 写成功、有的出错/未完成 |
| 失败 | 一个 QC 都没写成功（解析失败、工具块损坏、全部模型失败等） |
| 跳过 | 合理跳过：已有手写 `$lod`、面数低于门槛、无模型、模型文件缺失等，**不算失败** |
| 已停止 | 运行被用户停止，该项还没处理完 |

判定规则（任务级）：没处理过 → 取消→已停止；该任务展开出 0 个 QC → 失败；全部 QC 跳过且无错误 → 跳过；
一个都没写入 → 失败；有错误或没全部完成 → 部分完成；否则完成。

## 10. 运行日志

- 标题只有「运行日志」；不再在标题栏显示条数/错误摘要。无日志时「复制」「清空」置灰不可点，展开卡片可看「还没有日志」。

- `Ctrl+L` 展开/折叠；折叠时只留标题行。
- 日志最多保留 4000 行（超出从最早的丢）；运行日志会同时写文件（见「报告与日志位置」）。

## 11. 报告

每次运行都会写一份 Markdown 总报告：

- 文件名：`_LOD运行报告_MMdd_HHmmss.md`；运行日志：`_LOD运行日志_yyyyMMdd_HHmmss.txt`（UTF-8 带 BOM）。
- 内容：工具版本/开始时间/用时/工程目录/方案/写入方式；统计表（根 QC、唯一模型、简化任务成功/失败、写入/跳过/出错 QC、
  试编译、原始面数 → 末级面数、错误/提示数）；逐项结果表；跳过原因表；按 QC 分组的错误；提示；**还原方法**；下一步建议。
- 位置（设置 → 常规 → 日志与报告位置）：`QC 目录旁`（默认；实际写在**本次任务的根目录**，通常是工程根）、
  `exe 旁的「LOD日志报告」`、`自定义目录`。目录不可写时自动回退（报告层按 报告目录 → 工程根 → 临时目录 依次尝试），绝不因报告让运行失败。
- 运行完成后：HUD「报告」按钮、页脚「查看报告 ›」、Toast（有失败时）都能打开它。

报告里的「还原方法」会按本次是否备份、是否合集模式给出对应说明。

## 15. 哪些情况会被跳过 / 判错

**跳过（不算失败）**：

- 任务文件夹不存在 / QC 文件不存在 / 模型文件不存在；
- 整个文件夹没有 QC，也没有 `.glb/.smd`；
- QC 里没有 `studio` 条目；或有的条目都不可处理（文件缺失、不是 glb/smd、带 `innode`、只按文件名在别处找到）；
- 模型面数低于「面数门槛」，或该 QC 的模型全部低于门槛；
- QC 里已有别人手写的 `$lod`/`$shadowlod`，且没开「覆盖手写 $lod」（合集模式不受此限）；
- 本次没有可写的 `$lod` 条目（比如所有模型都简化失败）。

**判错（显示失败）**：

- QC 读取失败；`$modelname` 缺失只是提示，不单独判错；
- 工具标记块不完整（有开始标记缺结束标记）——**拒绝修改该 QC**；
- 模型读取/解析失败（GLB 损坏、SMD 不是 reference 网格等）；
- SMD → GLB、GLB → SMD 转换失败；
- 写 QC 失败（被占用/只读/权限）；备份失败同样导致该 QC 不修改并记错；
- 试编译失败（QC 已经写入，失败只作为错误记录，不回滚）；
- 没有可用的 Blender（批量必须用 Blender）。

## 16. 还原 / 回滚

- **QC**：改之前生成的 `xxx.qc.lodbak` 是**第一次修改前的原件**（永不覆盖）；之后每次修改前另存
  `xxx.qc.lodbak_MMddHHmmss`（同一秒再冲突时追加 `_2`、`_3`…）。把想回退的那份改回 `.qc` 即可还原。
  备份位置在设置 → 常规：QC 旁 / exe 旁的 `LOD备份`（按工程相对路径镜像） / 自定义目录。
- **独立 `_LOD.qc`**：删掉 `_LOD.qc` 后，原 QC 里还要删掉那一行 `$include "xxx_LOD.qc"`（下次运行会自动移除旧块/旧文件）。
- **生成的 LOD 文件**：`*_lodN.glb` / `*_lodN.smd` 可以直接删；QC 里引用了它们，删之前先还原 QC。
- **关闭备份**：没有 `.lodbak`，只能手工改回（设置里会红字提醒）。
- 工具不会删除你的唯一副本；任何写入失败都会尽量保持原文件（必要时留下 `.old_*` 副本并在错误里说明）。

## 17. 常见问题（FAQ）

**Q：点了「开始生成」没反应？**
A：看 HUD 副行与提示条。最常见是：队列空、LOD 参数非法（鼠标悬停「开始生成」看原因）、没有指定 Blender、Blender 跑不起来、
开了试编译但没设编译器、目标目录不可写、`Queue`/参数在锁定状态。

**Q：能撤销吗？**
A：能，见上一节 `.lodbak`。工具不会删除任何原文件。

**Q：带表情（形态键）的模型能做吗？**
A：能。减面前会清掉形态键（LOD 不需要表情）；`nofacial` 只影响远距离是否冻结表情。

**Q：减面后贴图接缝、硬边会裂开吗？**
A：导入时先按位置合并重合顶点（包围盒 1e-6 比例）再减面，UV/法线是 loop 数据仍保留；接缝与硬边不会因为减面裂开。

**Q：中文 / GBK 编码的 QC？**
A：写回沿用原 QC 的编码、BOM 与换行，不会乱码（报告与日志里会显示编码探测结果/警告）。

**Q：为什么队列里的项显示「跳过」？**
A：悬停或双击看原因；切到「跳过」页签可以看全部跳过项。

**Q：为什么顶栏三个状态点不动？**
A：顶栏现在只有**一个环境状态灯**（避免信息碎片化）：绿「环境正常」表示 Blender 可用、权限正常、编译器要么没配要么可用；
红「环境异常」说明至少一项有问题，鼠标悬停看明细，点击直接打开「运行环境诊断」。改 Blender / 编译器走菜单 →「打开设置 → 引擎」。

**Q：为什么管理员运行时拖不进文件？**
A：Windows 的 UIPI 限制。用「导入」按钮即可。

**Q：同时开多个工程/多次运行？**
A：一次运行会合并所有任务统一去重；同一个模型只简化一次、同一输出路径只跑一次。想分开跑就分两次。

**Q：`$lod` 的距离单位到底是米还是 HU？**
A：HU（游戏单位，1 HU ≈ 1.9 cm）。官方 zoey 的 10/15/25/50 就是 HU。

**Q：为什么 `$shadowlod` 不生成？**
A：实测会让 studiomdl 崩溃；本工具不碰阴影 LOD（覆盖模式只会把已有的 `$shadowlod` 注释停用）。

**Q：LOD 文件生成在哪里？**
A：模型文件同目录，命名为 `<模型名>_lodN.glb`（SMD 工程为 `.smd`）。

**Q：并行数怎么设？**
A：默认自动 `min(核数/2, 空闲内存GB/1.2, 8, 任务数)`。16G 内存建议 ≤6；减面时卡顿就调低，机械硬盘建议 1–2。

**Q：试编译失败但 QC 已经写了，会不会坏？**
A：不会。试编译只是校验（会写游戏目录的 mdl）；报告里会列出错误行，QC 与备份都在。
试编译失败不会自动回滚已写入的 `$lod`。

**Q：为什么「独立 _LOD.qc」模式原 QC 里不只有一行？**
A：原 QC 里会多一个工具标记块：几行说明注释 + 一行 `$include`。这是为了幂等替换与不误删你的内容。

**Q：启用了「跳过主模型」但清单是空的？**
A：需要先打开开关，再点「选择要跳过的 QC…」；清单按 QC 绝对路径匹配。

**Q：报告默认在哪里？**
A：设置里叫「QC 目录旁」，实际写到本次任务的根目录（通常是工程根）；不对时可在设置里改成 exe 旁或自定义固定目录。

**Q：日志里的时间是本机时间吗？**
A：是。

**Q：可以同时开两个工具窗口吗？**
A：不能——单实例。再次双击可执行文件会把路径交给已打开的窗口并把它激活。

**Q：怎么打开使用说明？**
A：菜单 →「查看使用说明」。单 exe 部署时需把 `docs\03_使用说明.md` 放在 exe 旁或 exe 旁的 `docs\` 下，
否则会提示"没有找到使用说明"。

## 20.1 术语表

| 术语 | 含义 |
|---|---|
| HU | Half-Life Unit，Source 引擎的长度单位；1 HU ≈ 1.9 cm。`$lod` 的切换距离就用它 |
| QC | Source 模型的编译脚本（`.qc`），描述 `$model`、`$bodygroup`、材质、动作等 |
| SMD | Source Model Data，文本格式的模型/骨骼数据（reference 网格） |
| GLB | glTF 2.0 的二进制单文件格式；本工具用 Blender 处理和产出 LOD 的主格式 |
| LOD0 | 原始模型；工具生成的是 LOD1..N（`*_lod1.glb`…） |
| `$lod` | QC 里按距离替换模型的指令块；工具注释 + 距离 + `replacemodel` 行组成 |
| `$shadowlod` | 阴影 LOD；本工具不生成（实测会让 studiomdl 崩溃） |
| nofacial | `$lod` 块里的选项：远距离不加载面部表情数据 |
| innode | studio 条目的多子节点参数；批量处理不支持，会跳过 |
| studiomdl / nekomdl | L4D2 的模型编译器；nekomdl 是社区分支，试编译用它 |
| `.lodbak` | 工具改写 QC 前的备份文件（第一次的原件，永不覆盖） |
| 独立 QC | 写入方式之一：生成 `xxx_LOD.qc`，原 QC 加一行 `$include` |
| 合集 | 写入方式之一：只输出 `_LOD合集.qc`，不改任何原 QC |
| 包装 QC | 给没有 QC 的散落 `.glb/.smd` 自动生成的 `自动LOD_<模型名>.qc` |

## 13. 常见拒绝修改的原因（数据安全优先）

工具在写 QC 之前会做几项安全检查，**任何一项不通过就一个字节都不改**，并在日志/报告里给出中文原因：

| 提示 | 原因 | 怎么处理 |
|---|---|---|
| 「文件是只读的，已拒绝修改」 | QC 或目录被设成只读 | 右键 → 属性 → 去掉「只读」，或 `attrib -R` 后重跑 |
| 「编码与 BOM 不一致 / 无法无损解码」 | 文件带 UTF-8 BOM 但正文其实是 GBK（或 UTF-16 等） | 用编辑器另存为「UTF-8 无 BOM」或「ANSI/GBK」，再重跑 |
| 「工具标记块不完整」 | 上次写入被中断/手改过标记块 | 用同目录的 `.lodbak` 还原该 QC，或手动删掉残留的标记块起止行 |
| 「文件被占用」 | 文件被别的程序锁着（编辑器/编译中） | 关掉占用它的程序再重跑 |
| 「备份失败，已中止」 | 备份目录不可写 | 检查 `LOD备份` 目录权限，或把设置里的备份位置改到可写目录 |

> 这些检查故意"宁可不动"，因为 QC 是用户的手工艺品：**拒绝修改**永远比**改坏**好。
