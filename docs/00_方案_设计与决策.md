# 远景工坊 · L4D2 自动 LOD 工具 —— 从零重写方案

> 文档性质：**方案与决策记录**（写码前定稿，后续变动按日期追加，不改历史结论）。
> 版本：方案 v1.0（2026-11-15）
> 目标程序：`L4D2LOD远景工坊.exe` v7.0.0（全新代码，不引用、不编译、不复制旧项目任何源码）

## 0. 一句话

给 L4D2 的模型工程自动生成多级 LOD：找出工程里真正会被编译的 QC，解析出每个模型引用，用 Blender 按"距离带 + 保留比例"减面成 `*_lodN.glb|smd`，再把 `$lod { replacemodel ... }` 幂等、可还原地写回 QC，最后出报告。新程序把这套能力**从零重写**为一个单文件 exe，并重新设计整个前端。

## 1. 需求理解

### 1.1 用户与场景

- 用户：L4D2 模组作者（中文），**不懂编程、不用命令行**，交付物必须是可双击运行的 exe。
- 典型场景：手上有一个模型工程目录（`工程文件/8人自动编译/…`），里面有若干 QC、SMD/GLB、以及作者自己的 `批量编译.bat`。作者希望"一键给所有模型加 LOD"，然后照旧双击自己的 bat 编译。
- 单次规模：几个到上百个 QC；每个 QC 引用几个到几十个模型；模型几千到几万面；一次运行几分钟到几十分钟。
- 环境：Win10/11、可能 125%/150% 缩放、工程路径含中文/空格/超长、可能开着火绒等安全软件、可能以管理员运行、Blender 4.0/4.1/4.2 已安装。
- **用户明确授权**：前端设计、后端设计、技术选型全部由实现方决定；优先保证质量。

### 1.2 核心功能（必须有的，P0）

| # | 能力 | 说明 |
|---|---|---|
| F1 | 任务导入 | 文件夹 / QC / GLB / SMD 四种；拖放、按钮、右键；自动只读扫描出规模 |
| F2 | 根 QC 发现 | 优先解析工程里的 `*.bat` 中 `nekomdl` 命令行参数；否则扫描含 `$modelname` 且未被 include 的 QC；排除本工具生成的 QC |
| F3 | QC 解析 | 递归 `$include` 链（含 `$cd/$pushd/$popd`）；收集 `$model`（主模型）、`$body`、`$bodygroup { studio … }`；解析模型文件路径（大小写、正/反斜杠、无扩展名、SMD 子目录、兜底同名）；保留编码/BOM/换行 |
| F4 | 全局去重 | 同一模型文件被多个 QC/多个条目引用时只简化一次；同一输出路径只跑一次 |
| F5 | Blender 减面 | 每个模型 × 每级一个任务；导出 `<base>_lod<N>.glb`（SMD 则 `<base>_lod<N>.smd`）；"质量优先"按连通块分配面数预算；焊接重合顶点避免接缝开裂；清形态键、清自定义法线后按角度平滑 |
| F6 | $lod 注入 | 三种写入方式：原 QC / 独立 `_LOD.qc` + `$include` / 仅合集；工具标记块幂等替换；缺结束标记拒绝删改；可选注释停用已有手写 `$lod`/`$shadowlod`；备份 `.qc.lodbak`（永不覆盖，后续带时间戳）；原子写 + 失败回滚；`nofacial` 可选；`CultureInfo.InvariantCulture` 写数字 |
| F7 | 跳过规则 | 已有手写 $lod 且未开覆盖、文件缺失、非 glb/smd、innode、面数低于门槛、无可处理模型、`$model` 跳过清单 —— 每条都要有可读原因 |
| F8 | 试编译（可选） | 调 `nekomdl.exe` 编译改动过的 QC，读回 `.dx90.vtx` 验证级数/切换点/每级面数 |
| F9 | 队列与状态 | 6 态（待处理/处理中/完成/部分完成/失败/跳过）；筛选页签 + 搜索；多选；键盘操作；运行中锁定；逐项结果与原因 |
| F10 | 报告与日志 | 运行日志（屏幕 + 文件）、总报告（Markdown，逐项结果/跳过原因/错误/提示/面数汇总/还原说明）；报告位置三选 |
| F11 | 设置 | 引擎路径、外观（浅/暗/跟随系统）、行为（恢复任务、成功弹窗、面数门槛、报告/备份位置）、LOD 高级（质量优先/覆盖手写/试编译/跳过主模型/nofacial/并行数）、诊断 |
| F12 | 预设 | 内置 8 个（对齐官方 zoey 实测数据）+ 用户自定义预设（存/删/恢复） |
| F13 | 取消与安全 | 一键停止（杀全部 Blender）、已完成文件保留、不再改 QC；关闭窗口时结束子进程；异常退出不留孤儿进程 |
| F14 | 环境自检 | 权限（管理员/低完整性/目录可写）、Blender/编译器探测与版本、设置文件位置、诊断报告可复制 |
| F15 | 交付形态 | 单个 exe，双击即用；无需安装运行时（.NET Framework 4.8 是 Win10 1903+/Win11 内置）；有文件版本资源；自带图标；单实例 |

### 1.3 明确不做（防止范围膨胀）

- 不做内置简化器 / `--no-blender`：旧版已证明质量不可接受，只保留 Blender 路线。
- 不生成 `$shadowlod`：实测会让 studiomdl 崩溃。
- 不做安装包 / 自动更新 / 联网功能 / 遥测。
- 不做多语言（只有简体中文界面）。
- 不做 32 位构建（x64 Win10+ 均为 64 位进程；WPF 默认 AnyCPU）。
- 不接管用户的编译流程：不批量替用户执行 `批量编译.bat`（只可选逐个 QC 试编译校验）。
- 不做模型预览/3D 视口（成本高、与本工具核心价值无关）。
- 不修改用户的 `.bat`、材质、贴图、模型源文件（只读它们，产出 `_lodN` 与 QC 注入）。

### 1.4 与旧版的关系

- 两个 exe 可以共存；新程序**不读写旧程序的设置文件**，只在首次启动时**只读导入**一次旧配置（引擎路径、LOD 参数、用户预设、选项、上次任务列表），导入后写自己的配置。
- 新程序识别的 QC 标记块与旧版**文本一致**（`//>>> L4D2 自动 LOD 工具 生成块 开始 >>>` 等），因此旧版写过的工程可以被新版原地接管（旧块被整块替换而不是叠加）；`// [autoLOD 已停用] ` 前缀同样沿用，避免二次停用。
- 新增识别：旧版生成的 `_LOD.qc`、`_LOD合集.qc`、`自动LOD_*.qc` 视为工具产物，不当根 QC。

## 2. 技术选型

### 2.1 候选与结论

| 选项 | 时长/体积/依赖 | 结论 |
|---|---|---|
| **.NET Framework 4.8 + WPF**（选定） | 单 exe ≈ 0.6–1.6 MB；零安装（Win10 1903+/Win11 自带 4.8）；WPF 矢量渲染、DPI 友好、XAML 布局/主题/动画成熟；用便携 .NET SDK 8 编译（C# 12 语言特性） | ✅ |
| WinForms 自绘（旧版路线） | 单 exe 小；全部靠 GDI+ 手绘，UI 代码量巨大、DPI/主题全靠自己 | ✗ 重写成本高、复用旧思路 |
| .NET 8 + WPF（框架依赖） | 需用户装 .NET 8 Desktop Runtime（本机有，别的机器不一定） | ✗ 破坏"双击即用" |
| .NET 8 自包含单文件 | ≈150 MB | ✗ 体积不可接受 |
| WebView2 + React（FIELD 路线） | 需 WebView2 运行库 + 分离的 wwwroot/DLL；冷启动慢、缓存/调试口问题多 | ✗ 对"单 exe 工具"过重 |
| Electron / Python 打包 | 体积大/启动慢/杀软误报 | ✗ |

### 2.2 编译链（本机实测可行）

- 编译器：便携 .NET SDK 8.0.404（`C:\Users\TPP\.tools\dotnet-sdk-8.0.404\dotnet.exe`），`dotnet build/publish -f net48`；SDK 自动还原 `Microsoft.NETFramework.ReferenceAssemblies.net48`（已缓存于 `%USERPROFILE%\.nuget\packages`，离线可重建）。
- 语言：`<LangVersion>latest</LangVersion>`（C# 12），目标框架 `net48`。可用 record/模式匹配/可空引用/集合表达式等；**不用**仅 .NET Core 才有的 API。
- 产物：`dotnet publish` 后复制 `dist\L4D2LOD远景工坊.exe`；资源（`app.ico`、`blender_backend.py`）以 `<EmbeddedResource>` 编进 exe；不产生旁挂 dll。
- 版本资源：`<Version>7.0.0</Version>` 等，右键属性有真实版本号（旧版缺失，本次修复）。
- 构建脚本 `build.ps1`：自动定位 SDK（环境变量 `DOTNET_EXE` → 默认路径 → `dotnet`）→ 还原 → 发布 → 复制到 `dist\` → 打印体积/SHA256/版本 → 可选 `-Clean`、`-NoDist`。

### 2.3 运行时依赖

- 仅 .NET Framework 4.8（Win11 26200 实测 4.8.09221）。WPF、GDI、Win32 都在系统内，无第三方 NuGet 包（引擎/UI 全部手写，无外部运行时依赖）。
- Blender 4.0/4.1/4.2（用户已有；程序内可探测版本、可指定路径）。
- `nekomdl.exe` 可选（只有开"试编译"才用）。

## 3. 架构

### 3.1 分层

```
┌──────────────────────────── Presentation（WPF, net48）────────────────────────────┐
│  Views (XAML)  ←→  ViewModels (MVVM, INotifyPropertyChanged/RelayCommand)          │
│  Theme tokens (Light/Dark, DynamicResource) · Controls (RangeCard/Progress/Toast)  │
└───────────────▲───────────────────────────────────────────────────────────────────┘
                │ IProgress / IBatchObserver / async commands（UI 线程只做展示）
┌───────────────┴──────────────────── Engine（纯 .NET，无 UI 依赖，可 headless）──────┐
│ BatchPlanner（只读计划） → BatchRunner（执行：Blender → 注入 → 试编译 → 报告）        │
│   ├ ProjectScanner  · QcParser/QcWriter  · Smd/Glb codecs                          │
│   ├ BlenderScheduler（进程池/看门狗/崩溃续跑/取消） + 内嵌 blender_backend.py        │
│   └ NekomdlRunner + VtxInspector · ReportWriter · RunLogWriter · Diagnostics       │
│  共享：AppSettings/LodPreset/FileUtil/JobObject/Win32                               │
└────────────────────────────────────────────────────────────────────────────────────┘
```

**关键约定**

- Engine 不引用 `System.Windows.*`（除 `System.Windows.Threading` 外一律禁用），保证可以 `--batch`/`--selftest` headless 跑；Engine 里禁止 `MessageBox`、禁止直接读 UI。
- UI 只通过 ViewModel 调用 Engine；Engine 的进度/日志通过接口回调，UI 侧封送 Dispatcher（日志批量刷入，避免逐行跨线程）。
- 所有面向用户的文案在 Engine 里写中文（引擎层产生日志/报告），UI 只做排版。

### 3.4 线程模型

- UI 线程：所有 `ObservableCollection` 变更、命令。
- 扫描：`Task.Run`，带 `CancellationToken`，结果整体回填（旧结果按版本号丢弃）。
- 运行：`Task.Run(BatchRunner.Run)`；`BatchRunner` 内部创建 Blender 工作线程池；进度/日志通过线程安全队列 + `DispatcherTimer`（50ms）批量刷 UI，避免日志风暴卡界面。
- 取消：UI 置"正在停止…"，调用 `cts.Cancel()` + `BlenderScheduler.KillAll()`；引擎在安全点退出，已完成 LOD 保留、QC 不再改。
- 关闭窗口：`OnClosing` → 若在运行则确认 → `KillAll()` → 等待后台退出（最多 3s）→ 关闭。

### 3.5 数据流（一次运行）

```
拖入/导入 TaskItem ──(后台只读)──> ScanResult（QC 数/模型数/跳过原因）
       │
   扫描预览 ──> BatchPlanner（只读，纯文件读取）

       │
   逐任务分摊结果 ──> 队列行状态 / 页脚 / Toast / 报告按钮
```

## 4. 引擎行为规格（重写自定的实现契约）

> 详细清单见 `docs/01_引擎规格.md`（由旧系统行为清点 + 本次重写决策组成）。此处只列不可动摇的硬约束。

### 4.1 QC 解析与注入（安全第一）

1. **识别工具的标记块**：`//>>> L4D2 自动 LOD 工具 生成块 开始 >>>` … `//<<< L4D2 自动 LOD 工具 生成块 结束 <<<`（沿用旧版文本，便于接管旧工程）。有开始无结束 → 该 QC 记为错误、**不修改**。
2. 注入 = 先把已有工具块整块擦除（保留原换行风格），再在根 QC 末尾追加"空行 + 开始标记 + 头部注释 + $lod 块 + 结束标记"。内容不变则不写盘（幂等）。
3. 手写 `$lod`/`$shadowlod`（工具块之外）：默认跳过该 QC；`Force` 时逐行加 `// [autoLOD 已停用] ` 前缀停用（作用于真正包含它的文件，可能是 include 文件）。
4. 备份：每个将要修改的文件先备份再写。备份名 `<qc>.lodbak`（第一次，永不覆盖；已存在则 `<qc>.lodbak_MMddHHmmss[_k]`）；备份位置三选（QC 旁 / exe 旁 `LOD备份\<工程相对路径镜像>` / 自定义）；**任何一个备份失败 → 整个 QC 不修改**；关闭备份时界面明确提示无法一键还原。
5. 原子写：tmp → `File.Replace`，失败走"原文件→.old→tmp→目标→删.old"的保守路径；任何失败都保证原文件仍在（原位或 `.old`），绝不删除唯一副本；失败时把同一 QC 已写的 include 文件恢复。
6. 编码：按 BOM/UTF-8 严格解码/GBK(936) 顺序探测；写回沿用原编码、BOM、换行；生成的 `_LOD.qc` 沿用根 QC 的编码与换行；数字一律 `InvariantCulture`。
7. `$lod` 块格式（每级）：
   ```
   // LOD1  切换距离 10  目标 99.7%  条目 3
   $lod 10
   {
       replacemodel "SMD\body" "SMD/body_lod1.glb"
       nofacial
   }
   ```
   - `replacemodel` 的第一参数**逐字**使用 QC 里写的字符串（`StudioRef.RawFile`），第二参数是从 QC 目录到 LOD 文件的相对路径（正斜杠还是反斜杠：沿用旧行为——`RelativeQcPath` 返回 Windows 相对路径 `..\`）。
   - 某级没有任何条目时不写该级（引擎会继续用上一级）。
   - `nofacial` 仅在设置开启时写。
8. `$model` 主模型：默认也生成 LOD（每级带 nofacial）；"跳过主模型"开启时按清单跳过（清单命中则 `$lod` 里不写该条目）。
9. `innode` 条目跳过；`$model` 的普通情况不跳过；`$bodygroup studio` 带 `innode` 跳过。

### 4.2 减面（Blender 后端）

- 内嵌 `blender_backend.py`（新写），运行时按内容 SHA-1 释放到 `%TEMP%\L4D2LOD远景工坊\backend\blender_backend_<hash>.py`，多线程/多进程安全复用；陈旧文件（>7 天）清理。
- 协议：任务 JSON（`{"quality":bool,"jobs":[{src,dst,ratio,shrinkInner,minFaces,guardPct,quality?,weight?}]}`）；stdout 逐任务 `BEGIN i`、`RESULT {json}`、人类可读 `OK/FAIL/DONE`；同时写 `<task>.jsonl`（flush+fsync）兜底；进程崩溃时从 jsonl 补齐已完成结果。
- 启动参数：`--background --factory-startup --python-exit-code 2 --python <script> -- <task.json>`；stdout/stderr UTF-8。
- 每任务处理：factory reset → 导入 glTF（`merge_vertices=True`，失败退化）→ 统计/清理（多用户数据 copy、`shape_key_clear`、按包围盒 1e-6 焊接、清自定义法线 + 按 60° 平滑；4.1+ 用 `shade_smooth_by_angle`，4.0 用 `use_auto_smooth`）→ 质量模式按连通块分配预算（min_faces=12、guard=35%）→ 逐块 Decimate(COLLAPSE, triangulate) → join 回原名 → 内层部件（名字含 `body`）沿法线内缩（0.09% 对角线，逐级 +15%）→ 导出 GLB（`export_apply=False`）。
- 质量模式关闭时使用全局比例，比旧版更快且不按块拆分（LOD1 比例 ≥99% 时自动走该模式）。
- 看门狗：距上一条结果超过 `20 分钟 + 每 10MB 加 5 分钟（上限 +100 分钟）` 判超时 → 杀进程，该任务失败，剩余任务换新进程继续；崩溃同理（每轮至少消掉一个任务，必然收敛）。
- 并行：`Workers`（0=自动：min(核数/2, 空闲内存GB/1.2, 8, 任务数)）；按任务权重（源文件字节数）降序轮流放入最轻的桶。
- 取消：`CancellationToken` 或 `KillAll()`（递增 epoch）；立即杀所有 Blender 子进程，未完成标"已取消"；每个 Blender 进程都放入 Job Object（KILL_ON_JOB_CLOSE），主程序被结束也不留孤儿。
- SMD 输入：先 C# 侧 SMD→临时 GLB（权重/骨骼），Blender 输出临时 GLB，再 C# 侧 GLB→SMD（恢复原骨骼 index/权重）。

### 4.3 输出命名与位置

- GLB：`<模型目录>\<原名>_lod<N>.glb`（N=1..级数）；SMD：`<原名>_lod<N>.smd`。
- 重跑覆盖同名 LOD 文件（写到 tmp 再替换，占用时给可读错误）；不删除用户目录里其他 `_lodN`（但会覆盖同名）。
- 独立 QC 模式：`<QC目录>\<QC名>_LOD.qc`；合集模式：`<工程根>\_LOD合集.qc`（不可编译，仅供粘贴）。
- 任务 JSON / 释放脚本 / SMD 临时 GLB 放 `%TEMP%\L4D2LOD远景工坊\`，正常结束即清理，异常残留由启动清理（>6 小时）。

### 4.4 试编译

- 只对"本次成功注入"的 QC 试编译；工作目录 = QC 目录；参数 `"<qc 路径>"`；标准输出编码系统 ANSI（中文 GBK）。
- 成功/失败以退出码判定；从 stdout/stderr 提取 ERROR/WARNING 行；按 `$modelname`（沿 include 链找）定位本次新生成的 `.mdl` 与 `.dx90.vtx`（带 2s 时间戳余量 + 大小写不敏感）；解析 vtx 得级数/切换点/每级面数写进日志与报告。
- 超时 10 分钟；找不到 nekomdl 时若"试编译"开启 → 开始前就拦下并提示去设置。

### 4.5 报告与日志

- 总报告：`_LOD运行报告_MMdd_HHmmss.md`（Markdown；每次运行一份，位置三选），内容：时间/用时/预设/写入方式/统计（根 QC、唯一模型、任务、注入、跳过、试编译、面数前后）、逐项结果、跳过原因表、错误与提示、还原方法、下一步。
- 运行日志：屏幕同屏显示 + 文件 `_LOD运行日志_yyyyMMdd_HHmmss.txt`（UTF-8 BOM）；内容与屏幕一致（含引擎阶段标题）。
- 报告/日志落盘目录解析失败一律回退（同级/工程目录/临时目录），绝不因报告设置让运行失败。

## 5. 前端设计（新）

### 5.1 设计定位

**"测距仪 / 量具"**：这不是一个数据后台，而是一台**校准过的量具**——用户在这里量"距离—细节"的对应关系。设计语言来自精密仪器的正面板：石墨/纸白两种机身、1px 发丝刻度、单一"Blender 橙"信号色、压缩体数字（Bahnschrift）、量测式分区与刻度线。所有装饰都必须回答"这是量测信息吗"。

> 与旧版的关系：旧版是"明日方舟式游戏终端"（青信号 + 大编号 + 终端动画）。新版不复刻：信号色改橙、编号不再当装饰、去掉扫描线/擦入等游戏化动效、面板从"卡片堆叠"改为"仪表分区 + 刻度"。用户体验目标不变：**信息密度高、层级清楚、动作明确**。

### 5.2 品牌

- 中文名：**远景工坊**（LOD 即"远景"的细节表现；"工坊"= 动手改模型的地方）

- 版本：`7.0.0`（新一代；与经典版 v4.1.1 / FIELD v5.1.0 区分）
- 标记（mark）：24×24 矢量——四根递降竖条（LOD 逐级衰减）+ 一条斜向"测线"穿过顶端 + 右下角一个点（远点）。exe 图标由同一几何在 16/24/32/48/64/128/256 重绘打包。
- 语感：说明性、动作明确、不用营销词；错误提示给原因 + 下一步；空状态给入口。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| WPF 自绘标题栏在部分 DPI/多屏下错位 | 窗口操作异常 | 用 `WindowChrome` 官方机制；在 100/125/150 与最大化/还原下逐项截图验证；保留 `-NoCustomChrome` 开关回退系统标题栏 |
| Blender 4.2+ API 变化 | 减面失败 | 后端脚本对导入参数、平滑 API、导出参数做 try/except 回退；实测 4.0/4.1，4.2+ 按文档写兼容分支 |
| GBK/异常编码 QC 写坏 | 用户工程损坏 | 原子写 + 备份 + 原文件永不删除；自测覆盖 GBK/BOM/CRLF/混合换行；备份失败即中止 |
| 长路径/中文/权限 | 运行失败 | 全链路 `Path.GetFullPath` + 长路径前缀容错；写前可写性测试；错误给可读原因 |
| WPF 首次渲染慢 / 大列表卡顿 | 体验差 | 虚拟化列表；日志批量刷入；避免全量 INotify 刷新；启动测量与优化 |
| 单实例/后台残留 | 进程残留 | Job Object + 关闭时 KillAll + 等待退出；进程表验收 |
| 测试环境缺少真实工程/编译器 | 覆盖不全 | 合成工程 + 真实工程副本；nekomdl 缺失路径也做专门测试 |

**回滚**：新程序独立目录、独立 exe、独立设置；不修改旧程序与 E: 部署（部署需用户另行批准）。新程序自身产生的 QC 修改都有 `.lodbak` 可还原。
