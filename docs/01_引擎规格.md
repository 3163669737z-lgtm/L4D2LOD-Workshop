### 2.3 FileUtil（`src/Engine/FileUtil.cs:FileUtil`）

`WriteAtomic(targetPath, data)` 的**精确步骤**（QC 安全的基础，不要换实现）：

1. `target = Path.GetFullPath(targetPath)`；临时文件 `target.tmp_<8位guid>`；
2. `File.WriteAllBytes(tmp, data)`；写临时文件失败 → 删 tmp 并抛；
3. 目标不存在 → `File.Move(tmp,target)`；失败删 tmp 抛；
4. 目标存在 → `File.Replace(tmp,target,null)`；成功返回；
5. `Replace` 失败后若目标已不存在而 tmp 在 → 尝试 Move；
6. 保守回退：`File.Move(target, target.old_<tag>)` → `File.Move(tmp,target)` → 删 old；
7. 两步都失败：把 old 移回 target；删 tmp；抛 `IOException`，消息含"文件可能被占用或只读，原文件未改动"；
   若 old 也移不回，消息提示"原文件已保留为 xxx.old_xxx，请手动改回原名"。

> 不变量：**任何失败路径都不删除唯一副本**；目标目录必须已存在（调用方负责建目录）。

其他成员：`ReadAllBytesShared`/`ReadAllLinesShared`（`FileShare.ReadWrite|Delete`，允许编辑器/杀软同时持有）、
`TestWritable(dir)`（建探针文件再删，返回 null=可写，否则中文原因）、`IsLocked`（独占打开探测）、
`WriteBytesSafe`（LOD/模型输出用：占用时先删再写，仍失败给可读原因）、`MakeRelative(fromDir,target)`（Windows 反斜杠，
跨盘返回绝对路径）、`RelativeDisplay`、`EnsureDir`、`Normalize`（绝对路径去掉尾分隔符）、`LongPath`（≥250 字符加 `\\?\` / `\\?\UNC\`）、
`DetectNewLine`（含 `\r\n` 则 CRLF，否则 LF）、`NormalizeNewLines`、`DirectorySize`、`FormatBytes`。

### 3.3 QcTextFile：编码探测与写回

探测顺序（`QcTextFile.Decode(bytes,out encoding,out bom)`，注释与实现逐条对应）：

1. 前三字节 `EF BB BF` → UTF-8 带 BOM（`Bom=true`，正文去掉 BOM）；
2. 严格 UTF-8（`new UTF8Encoding(false, true)`，非法字节抛异常）→ UTF-8 无 BOM；
3. `Encoding.GetEncoding(936)`（GBK）；
4. `Encoding.Default`（系统 ANSI）。

换行：`FileUtil.DetectNewLine(text)` 只用于决定**新追加内容**的换行风格（正文出现 `\r\n` 用 CRLF，否则 LF）；
**原有行一律原样保留，包括混合换行**（`QcLexer.TryRemoveToolBlock` 只删除标记块所在行，不做全文归一化，保证重复运行字节幂等）。
解码：UTF-8 BOM 分支用严格 UTF-8，GBK 用严格解码；解出文本会用同一编码重编码并与原字节逐字节比较，**不一致就抛 `InvalidDataException` 拒绝修改**（不再静默写回替换字符）。
写回：`Write(text)` → `WriteAllText(FilePath,text,Encoding,Bom)` → `FileUtil.WriteAtomic`。
`Encode` 只在 `bom=true` 且编码是 `UTF8Encoding` 时加 BOM（GBK 永不加 BOM）。
读取用 `FileUtil.ReadAllBytesShared`（允许 QC 正在编辑器里打开）。

> 不变量：写回必须沿用**读入时探测到的编码、BOM、换行**；编码探测顺序不可"优化"（真实工程有 GBK/UTF-8 BOM 混用）。

### 3.4 QcLexer：文本不变量与标记块

**标记块文本（常量，与旧版逐字一致）**：

```text
//>>> L4D2 自动 LOD 工具 生成块 开始 >>>
...
//<<< L4D2 自动 LOD 工具 生成块 结束 <<<
```

- `QcLexer.MarkerBegin` / `MarkerEnd` 即上面两行；`DisabledPrefix = "// [autoLOD 已停用] "`。
- 所有"遮蔽"函数（`MaskComments`、`MaskToolBlocks`）都保证**长度与字符位置一一对应**：注释/块内容替换成空格，
  `\n`/`\r` 原样保留，因此遮蔽文本上得到的偏移可直接用于原文。
- `MaskComments`：字符串里的 `//`、`/* */` 不算注释；字符串不跨行（遇 `\n`/`\r` 结束）；未闭合字符串不吞后文。
- `MaskToolBlocks(text,out broken)`：按行扫描，`line.Trim().StartsWith(MarkerBegin)` 开始、`StartsWith(MarkerEnd)` 结束，
  整段（含标记行）替换为空格；**有开始无结束 → `broken=true` 且不遮蔽**（调用方必须拒绝处理该 QC）。
- `TryRemoveToolBlock(text,out result)`：移除所有块，结果换行统一 `\n`；缺结束标记 → 返回 false 且 `result=原文`
  （注释写明"绝不删到文件尾"）。
- `CommentOutForeignLod(rawText,out count)`：先遮蔽注释+工具块，切词定位工具块以外的 `$lod/$shadowlod`；
  向后最多看 4 个 token 找块起始 `{`（用 `FindMatchingBrace` 定位 `}`），整块逐行加 `DisabledPrefix`；
  `count`=停用块数；工具块不完整返回 -1 且原文不动。
- `Tokenize`：引号串（`Quoted=true`，不跨行）、`{`/`}` 独立 token、其余按空白切；`Pos` 为原文偏移。
- `QcToken.IsWord(word)` 大小写不敏感且要求非引号；`IsBrace` 判断 `{`/`}`。
- `FindMatchingBrace(masked,open)`：字符串里的花括号不算；找不到返回 -1。
- `LineStarts/LineOf`：字符偏移 ↔ 0 起行号（`LineOf` 用二分）。

### 3.5 QcParser：include 链与模型收集

`QcParser.Parse(qcPath)`（不抛异常；失败写 `QcInfo.ReadFailed/Warnings`）：

- `MaxIncludeDepth = 8`；`Visited` 为大小写不敏感 HashSet（防环）；根文件先读一次用于探测编码/BOM/换行；
- 递归 `Collect(file,depth,st)`：`depth>0` 时遇到 `IsToolGeneratedQc` 直接 return（不跟进工具产物）、
  已访问 return；读取失败只记 warning；`depth>0` 记入 `IncludedFiles`；
  根文件含 `MarkerBegin` 记入 `ToolMarkerFiles`；`MaskToolBlocks` 返回 broken 记入 `ToolBlockBrokenFiles`；
- 状态**整个 include 链共享**：`CurDir`（`$cd/$pushd/$popd` 后的当前目录）、`DirStack`、`BgIndex`；
- 指令处理（对已遮蔽注释/工具块的 token 流）：
  - `$modelname`：第一个出现的生效，反斜杠转正斜杠；没找到 → `Warnings` 提示"没有找到 $modelname"；
  - `$staticprop`：`IsStaticProp=true`；
  - `$cd`/`$pushd`/`$popd`：改 `CurDir`/目录栈（`CombineDir` 用 `Path.GetFullPath(Combine(cur,arg))`，异常保持原值）；
  - `$lod` / `$shadowlod`：把手写块所在文件加入 `ForeignLodFiles`（工具块已被遮蔽，所以扫到的就是手写的）；
  - `$include`：`FindInclude` 候选顺序 = 当前目录 → 根 QC 目录 → 声明文件目录 → 根目录+纯文件名；第一个存在的生效，
    递归 `Collect(depth+1)`，消费参数 token；
  - `$body <name> "<file>"`：生成条目，`Bodygroup=name`、`BodygroupIndex=BgIndex++`、`HasFacial` 不设置；
  - `$bodygroup <name> { ... }`：只识别**最外层**（braceDepth==1）的 `studio "<file>"`；同一行紧跟的 `innode <arg>` 记入 `Innnode`；
    一个 bodygroup 内所有 studio 共享同一 `BgIndex`；块结束后 `BgIndex++`；
  - `$model <name> "<file>" [ { ... } ]`：条目 `IsMainModel=true`、`BodygroupIndex=-1`、`Bodygroup="(主模型 name)"`；
    块内扫描 `flexfile/flexcontroller/localvar/$include/flex/flexpair` → `HasFacial=true`，`innode` → `Innnode`。
- `$modelname` 查找（`FindModelName(qcPath,maxDepth)`）：同样的 include 链推进，返回**第一个** `$modelname`（反斜杠转正斜杠），
  找不到返回空串；试编译用它定位产物。
- `IsToolGeneratedQc(path)`：文件名以 `_LOD.qc` / `_autoLOD.qc` 结尾，或以 `_LOD合集` / `自动LOD_` 开头 → true。
  **注意**：`QcParser.IsToolGeneratedQc` 与 `ProjectScanner.IsGeneratedQc` 现在都认 `_auto.qc`（评审收口后已一致）。

### 3.6 QcPathResolver：模型路径解析优先级

`Resolve(entry,raw,declFile,curDir,rootDir,warnings)`（结果写回 entry，顺序敏感）：

1. 基目录候选（去重）：`curDir`（`$cd/$pushd` 后当前目录，跨 include 共享）→ `rootDir`（根 QC 目录）→ `declFile` 所在目录；
2. 每个基目录下依次尝试：
   - 有扩展名：`base\路径`；
   - 无扩展名：`base\路径.glb`、`base\路径.smd`（**.glb 优先**）；
   - `base\文件名`（去掉目录）；`base\SMD\文件名`；无扩展名再 `base\SMD\文件名.glb`；
3. 追加根目录的上一级：`up1\路径`、`up1\SMD\文件名`；
4. 第一个 `File.Exists` 命中即生效（`ResolvedPath=GetFullPath`，`Exists=true`）；
5. 全都没找到：在 `rootDir` 下按文件名 `EnumerateFiles(AllDirectories)` 兜底 → 命中只记 `Fallback=true`、`Exists=false`，
   并给 warning"按 QC 路径没找到；按文件名在别处找到同名文件…为安全起见未处理"。

`IneligibleReason(s)`：`null`=可处理；否则返回 `"fallback"` / `"missing"` / `"nonglb"`（扩展名不是 .glb/.smd）/
`"innode"`（`Innnode` 非空）。`SamePath(a,b)` 大小写不敏感比较。

### 3.7 QcWriter：幂等注入、备份与回滚

`QcWriter.Apply(info, toolBody, force, backup)` → `QcWriteResult{Success,Error,WrittenFiles,DisabledForeignLodBlocks,NoChange}`，
**不抛异常**（异常转 `Error` 中文）。`ApplyCore` 八步（顺序不可变）：

1. `force=true`：先处理 `info.ForeignLodFiles` 中**不是根 QC** 的 include 文件：
   读取 → `CommentOutForeignLod` → 有停用块则加入待写列表；读取失败或块不完整 → 整个 QC 不改并返回错误；
2. 读取根 QC（失败 → 不改）；`force` 时对根 QC 也 `CommentOutForeignLod`（块不完整 → 拒绝）；
3. 擦除根 QC 里的旧工具块：`text.IndexOf(MarkerBegin)>=0` 时 `TryRemoveToolBlock`；缺结束标记 → 失败，
   **文件一个字节都不动**；移除结果统一为 `\n`，写回前恢复成原文件换行风格；
4. 拼接新文本：`cleaned.TrimEnd('\r','\n')` + `nl` + `nl` + `MarkerBegin` + `nl` + body（保证以换行结尾）+ `MarkerEnd` + `nl`；
   `toolBody=null` 时表示"只移除旧块"，恢复为去尾部空行的默认结尾；与原文完全相同则不加入待写列表；
5. 待写列表为空 → `Success=true, NoChange=true`（**不写盘、不备份**，幂等重跑）；
6. 备份：`backup == null || backup.Enabled` 时，**先给所有待写文件逐个备份成功**，任何一个失败 → 整个 QC 不改；
7. 按待写顺序写（include 文件在前、根 QC 最后）；任何一个写失败 → 把已写的文件恢复成读入时内容，返回失败；
8. 成功：汇总 `WrittenFiles`、`DisabledForeignLodBlocks`。

`BuildLodBlock(info, plan, generatedLodFiles, skipMainModel, noFacial)`：只引用 `generatedLodFiles` 里存在的级
（绝对路径集合，大小写不敏感归一）；条目筛选顺序：跳过主模型（可选）→ `IneligibleReason` 非 null 跳过 →
按模型目录/基名/扩展名算 `<basename>_lod<N><ext>`。每级文本**逐字固定**（换行 `\n`，由 Apply 统一转换）：

```text
// LOD1  切换距离 10  目标 99.7%  条目 3
$lod 10
{
	replacemodel "SMD\body" "SMD/body_lod1.glb"
	nofacial
}
```

- 数字格式：距离 `0.###`、目标百分比 `(ratio*100)` 用 `0.#`、条目数整数；全部 InvariantCulture；
- `replacemodel` 第一参数 = `StudioRef.RawFile`（逐字），第二参数 = `FileUtil.MakeRelative(info.QcDir, lodFile)`（Windows 反斜杠）；
- 同级键去重：键为 RawFile，重复键保留首次位置、值以最后一次为准；
- 某级没有条目 → **整级不写**（编译时引擎会沿用上一级）；所有级都没条目 → 返回 null。
- `nofacial` 仅在 `noFacial=true` 时写；`skipMainModel=true` 时 `$model` 条目不写。

`WrapMarker(body,presetName,plan,isIncludeLine)` 生成工具块头注释 + body：

- 第一行：`// 预设: {presetName}（{plan.Summary()}）`；
- 第二行（InPlace）：`// 由「L4D2 自动 LOD 工具」生成；重新运行会整块替换，不要手工改这一段。`；
- 第二行（Separate 的 include 行）：`// $lod 写在旁边那个 _LOD.qc 里，本文件只加一行 include。重新运行会整块替换，不要手工改这一段。`。

`SeparateQcPath(rootQcPath)` = `<QC目录>\<QC名>_LOD.qc`。
`WriteSeparateQc(path,info,presetName,plan,block)`：文件头注释（工具名、生成时间、涉及模型、预设、参数、如何停用）+
空行 + block；**编码/BOM/换行沿用根 QC**（`info.TextEncoding/info.HasBom/info.NewLine`）；写失败返回中文错误。

`BackupFile(path,request,out error)`：

- `request==null` 或 `CentralBaseDir` 为空 → 备份在原文件旁；否则备份到
  `CentralBaseDir` + 文件相对 `ProjectRoot` 的目录镜像（`RelativeDisplay` 得到相对路径，非绝对才用）；
- 备份名 `<原文件名>.lodbak`；**已存在时**改为 `<原文件名>.lodbak_MMddHHmmss`，若仍冲突追加 `_2`、`_3`…；
  `.lodbak` 只保留"第一次修改前的原件"，永不覆盖；`File.Copy(full,bak,false)` 后验证存在；
- 返回备份路径或 null+error。

> 不变量：备份失败即中止、缺结束标记拒改、内容不变不写盘、任何失败都不删除唯一副本、失败回滚已写 include 文件。

## 4. 扫描 / 计划 / 执行

### 4.1 ProjectScanner（`src/Engine/Pipeline/ProjectScanner.cs:ProjectScanner`）

`FindRootQcs(rootDir, log)` — 根 QC 发现优先级：

1. 递归枚举 `*.bat`（`SafeEnumerateFiles`：逐目录 try/catch、跳过 ReparsePoint、深度上限 64、visited 防环），
   剔除备份目录里的 bat，按路径排序；逐个 `ParseBat`，读到的 QC 依次加入（按绝对路径去重）；
   过滤备份目录与本工具产物；任何一个 bat 读到 QC → **直接返回该清单**（不再启发式扫描）；
2. 否则：递归枚举 `*.qc`，剔除备份与产物、排序；逐个用 `QcParser.ReadTextSmart` 读文本 → `QcLexer.StripComments`；
   含 `$modelname "` 的加入 `withModel`；收集 `$include "xxx.qc"` 的目标（`FindIncludeTarget`：QC 目录 → 工程根 → 同名兜底）；
   最终返回 `withModel` 中**未被任何 QC include** 的（剔除"片段 QC"）；
3. 备份目录判定 `IsUnderBackup`：路径含 `_LOD备份`，或任一路径段等于 `LOD备份`/`_LOD备份`；
4. `IsGeneratedQc`：`_LOD.qc`、`_autoLOD.qc`、`_auto.qc` 结尾；`_LOD合集`、`自动LOD_` 开头。

`ParseBat(batPath)` 规则：

- 用 `QcTextFile.Read` 解码（bat 常见 ANSI/GBK），按行处理；去首尾空白、去掉行首 `@`；
- 跳过空行；注释判定：行首 `::`，或 `^rem($|[\s.:,;=(])`（大小写不敏感，避免 `remote` 误伤）；
- 行内**不含** `nekomdl`（大小写不敏感）跳过；
- 变量展开：`%~dp0` → bat 目录+结尾反斜杠；`%CD%` → bat 目录；并修正 `%~dp0\\x.qc` 的双反斜杠；
- 挑 QC 参数：优先**最后一个**以 `.qc` 结尾的引号串；否则**最后一个**裸 `.qc`（可多个 token，取后面的）；
- `Path.Combine(batDir, qc)` + `GetFullPath`，**文件必须存在**才计入；结果去重（大小写不敏感）。

`FindLooseModels(dir,maxDepth,log)`：递归找 `.glb/.smd`，深度默认 3；跳过 `_LOD*` 目录与 ReparsePoint；
排除文件名匹配 `_lod\d+\.(glb|smd)$`（本工具产物）；结果排序。

`WrapperQcPath(modelPath)` = `<模型同目录>\自动LOD_<模型名去扩展>.qc`。
`EnsureWrapperQc(modelPath,log)`：已存在 → 沿用（**绝不覆盖**）；不存在则按模板写（用 `SystemAnsi` 编码，无 BOM）：

```text
// 由 L4D2 自动 LOD 工具生成（源模型没有 QC，自动创建）
// 编译前请按需修改 $modelname / $cdmaterials；本文件已存在时工具不会覆盖它

$modelname "props/<name>.mdl"
$bodygroup "<name>"
{
	studio "<file>"
}

$cdmaterials "models/<name>"
$surfaceprop "default"

$sequence "idle" {
	"<file>"
	fps 30
	activity "act_idle" 1
}
```

编码说明：程序清单声明 `activeCodePage=UTF-8`，`Encoding.Default` 会变成 UTF-8；studiomdl 仍按系统 ANSI 读 QC，
因此 `src/Engine/Pipeline/SystemAnsi.cs:SystemAnsi` 读注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Nls\CodePage\ACP`
得到真正的系统 ANSI（中文=936），拿不到才退回 `Encoding.Default`。包装 QC / nekomdl 管道编码都用它。

### 4.3 BatchPlanner（只读）

`BatchPlanner.Build(tasks, rootDir, options, observer, cancel)` → `BatchPlan`；**不写任何文件、不启动 Blender**。
内部 `DoBuild` 五阶段（日志/Stage 分别为 `── 1/5 … ──` 到 `── 5/5 ──`）：

1. **展开任务**：校验 LOD 参数（`plan.Validate()`，错误只记日志）；遍历 tasks：
   - `Folder`：不存在 → `exp.Error="文件夹不存在"`；`FindRootQcs`；若 0 个根 QC → `FindLooseModels(path,3)`，
     仍 0 → `exp.Error="没有 QC，也没有 .glb / .smd"`；否则为每个散落模型登记包装 QC
     （已存在则直接当 QC；不存在则记入 `PendingWrappers` 与 `exp.WrapperModelPaths`）；
   - `Qc`：不存在 → 错误；否则加入清单；
   - `Glb/Smd`：不存在 → 错误；登记包装 QC（已存在/已登记则不重复）并加入清单；
   - QC 清单按**绝对路径**去重（大小写不敏感）。
2. **解析 QC**：包装 QC 尚未落盘 → 用 `MakeWrapperInfo` 合成 `QcInfo`；否则 `QcParser.Parse`（异常也转为 `ReadFailed` 的 Info）。
   动作判定顺序：`ReadFailed` → Error「读取 QC 失败」；`ToolBlockBroken` → Error；
   `HasForeignLod && !Force && OutputMode!=CollectionOnly` → Skip「已有手写 $lod（在 xxx）；要覆盖请在高级设置里勾选…」；否则 Process。
   随后 `PruneIncludedRoots`：若某 QC 的 `IncludedFiles` 含另一 QC，则被 include 的从清单剔除（互相 include 时保留先出现的），并记日志。
3. **收集模型 + 全局去重**：只处理 Action=Process 的 QC；`SkipMainModel` 且该 QC 在 `SkipMainQcPaths` 命中时跳过主模型条目；
   条目筛选（统计 fallback/missing/nonglb/innode 并各记一条汇总日志）；去重键 = **`ResolvedPath` 绝对路径**（大小写不敏感）；
   同一模型被多 QC/多条引用只建一个 `PlannedModel`，并记录所有 `Entries` 与 `RootQcs`。
4. **面数统计 + 生成任务**：SMD 用 `SmdCodec.Parse` 得 `TriangleCount`；GLB 用 `GlbCodec.CountTriangles`；
   读取失败 → 该模型所有根 QC 置 Error 并记日志；面数 `< MinTriangles` → `SkipReason`（不生成任务）；
   每级一个 `BlenderJobSpec`：
   - GLB：`Source=模型路径`、`Destination=<模型目录>\<base>_lod<N>.glb`；
   - SMD：`Source=%TEMP%\...\smd\<base>_src.glb`（占位，执行时才生成）、`Destination=<TempSmdDir>\<base>_lod<N>.glb`，
     最终产物 `<模型目录>\<base>_lod<N>.smd` 由执行器转回；
   - `Ratio=plan.Levels[li].Ratio`、`ShrinkInner=0.0009*(1+0.15*li)`、`MinFaces=12`、`GuardPercent=35.0`、
     `QualityOverride = ratio>=0.99 ? false : null`（LOD1 只降 0.3% 时走速度模式）、`Weight=源文件字节数`；
   - 输出路径去重（大小写不敏感）；重复给 Warn 并跳过该任务；确保目标目录存在。
5. **汇总动作**：Action=Process 且 `Models.Count==0` → Skip（原因区分"没有 studio 条目"与"无可处理模型"）；
   `Models` 非空但所有模型 `Jobs.Count==0` → Skip「模型面数都低于门槛」；逐条输出跳过/错误日志，并给出计划汇总。

`plan.HasWork = 有 Process QC 且该 QC 有模型 && JobCount>0`。

### 4.4 BatchRunner（执行）

`BatchRunner.Run(plan, options, observer, cancel)` → `BatchOutcome`；不抛异常（未预期异常记 `Errors`，`Ok=false`）。
`RecordingObserver` 记录全部日志行（报告/日志文件用）。流程：

0. **建包装 QC**：`plan.PendingWrappers` 逐个 `ProjectScanner.EnsureWrapperQc`；失败把对应 `BatchQcPlan.Action` 改 Error。
1. **Blender 减面**：
   - 收集 `plan.Models` 中 `Jobs.Count>0 && ReadError==null` 的模型；
   - **SMD 预处理**：`SmdGlbCodec.SmdToGlb(pm.SmdSource)` → 写 `pm.Jobs[0].Source`（临时 GLB）；失败记该模型所有根 QC 错误；
   - 把所有（模型,级）任务拍平成 `jobs` 列表；`stats.JobCount`、`stats.UniqueModelCount`；
   - `BlenderPath` 为空/不存在 → 尝试 `BlenderLocator.Find`，仍无 → 记错误、给所有 Process QC 错误、写报告后返回；
   - `BlenderScheduler.RunAll(jobs,{BlenderPath,Workers,QualityFirst,Log},cancel,progress)`；取消后记录"已停止"。
2. **汇总减面结果**：逐任务检查 `Ok && File.Exists(Destination)`；GLB 直接计入 `okDst`；SMD 则
   `GlbCodec.Read(临时GLB)` → `SmdGlbCodec.GlbToSmd(glb, pm.SmdSource)` → `SmdCodec.Write(最终 .smd)`；
   失败 → 失败计数并把错误摊到该模型所有根 QC；成功记 `after`（末级面数用）；清临时 SMD 源/中间 GLB；
   取消 → 不注入、写报告后返回。
3. **注入 `$lod`**：逐 `BatchQcPlan`：
   - Error → 记错误；Skip → 若该 QC 还带着上次的工具块（`RootHasToolMarker`）且非合集模式，`QcWriter.Apply(info,null,false,backup)`
     移除旧块（失败只警告）；记 `Skipped`/`SkippedQcPaths`；
   - Process → `BuildLodBlock`（可写内容为空 → 记 Skip，原因区分有无错误）；按 `OutputMode`：
     - `InPlace`：若上一次是 Separate 模式且原 QC 引用 `_LOD.qc`、该文件头含工具标识，则写完后**删除**该 `_LOD.qc`；
       `QcWriter.Apply(info, WrapMarker(block), Force, backup)`；
     - `SeparateQc`：`QcWriter.WriteSeparateQc(<QC目录>\<QC名>_LOD.qc, …)`，原 QC 写入
       `WrapMarker("$include \"<QC名>_LOD.qc\"", …, isIncludeLine=true)`；
     - `CollectionOnly`：`AppendCollection` 追加到内存，原 QC 一个都不改；最后写
       `<plan.RootDir>\_LOD合集.qc`（`QcTextFile.WriteAllText(..., UTF8(no BOM), bom=true)` → UTF-8 BOM；内容用 `AppendLine` 即 CRLF）；
   - 每个 QC 成功 → `Injected=true`、`InjectedQcPaths`。
4. **可选试编译**：仅当 `CompileAfter && !collectionMode && NekomdlPath 存在`；只试编译**本次注入**的 QC；
   `Nekomdl.Compile` 成功 → `CompileOk`，有 vtx 则摘要 `LOD<N>  面数 a → b → …`；失败把首条错误加入该 QC 错误；
   `CompileAfter` 但没编译器 → 只记 Warn 跳过。
5. **报告/日志**：`WriteReports` 构造 `ReportContext`（Root/Preset/Plan/Mode/Backup/StartedAt/Elapsed/Outcome/LogLines/CompileAfter），
   报告目录 `options.ReportDir ?? plan.RootDir`；`outcome.ReportPath/LogPath` 回填；异常只警告，绝不让运行失败。

`ComputeOk`：取消 → false；`outcome.Errors` 非空或任一 QC 有错误 → false；有任务但 `JobOk==0` → false；
没有注入任何 QC 时，只有"全部 QC 都合理跳过"（`SkippedQcCount>=QcPlans.Count` 且无 Error）才算成功。

取消语义：BatchRunner 在阶段边界检查 `cancel`；Blender 阶段由调度器立即杀进程；取消后**不再开始新的 QC 修改**，
已生成的 LOD 保留；已经处理完的 QC（成功注入的、或跳过路径上清理了旧工具块的）保留结果，其余 QC 原样未动；
报告照样写（含"用户中途停止"）。`--batch` 下 Ctrl+C 同样走此路径。

### 5.2 后端脚本释放（`BackendScript.cs`）

- `LoadBytes()` 只读一次缓存，`ContentHash` = SHA-1 前 8 位小写十六进制；
- `EnsureExtracted(out error)`：释放到 `%TEMP%\L4D2LOD远景工坊\backend\blender_backend_<hash>.py`；
  同名且字节一致 → 复用；内容不同 → 写唯一临时文件后删除旧文件再 `File.Move`；
  并发竞态（目标已存在）→ 内容一致则删临时文件复用，否则用唯一命名 `.py` 副本；
- 每进程只清理一次：该目录中与本版本无关、超过 `StaleDays=7` 天的脚本/临时文件；
- `ExpectedPath/SourceLineCount/SourceText` 供自测/诊断。

### 5.3 定位与版本探测（`BlenderLocator.cs`）

- `Find(hint)` 顺序：hint（目录→`blender.exe`；文件直接用）→ 注册表 `App Paths\blender.exe`（HKCU/HKLM × 32/64 视图，
  取默认值与 `Path`）→ 常见目录（`C:\Program Files\Blender Foundation`、`D:\`、`C:\Program Files`、
  `D:\Program Files\Blender Foundation`；子目录按版本号**降序**，即新版本优先）→ Steam 库（注册表 SteamPath/InstallPath +
  `steamapps\libraryfolders.vdf` 的 path/数字键，只认盘符路径）；
- `ProbeVersion(exe,timeoutMs=15000)`：跑 `blender --factory-startup --version`，stdout/stderr 都异步读防死锁，
  超时杀掉；取第一条以 `Blender ` 开头的行，否则第一条非 TBBmalloc 非空行；失败 null；
- `IsUsable(exe)` = 存在且探测成功。全部方法不抛异常。

### 5.4 调度器（`BlenderScheduler.cs`）

`RunAll(jobs, options, cancel, onProgress)` 返回与 jobs **同序同数量**的结果列表。要点：

- **Dst 去重**（`DedupOwners`）：键 = `GetFullPath(dst).ToLowerInvariant()`；同输出只执行第一次（owner），
  其余为 follower，owner 结果完成后复制给 follower（回调也逐个触发）；Dst 为空不参与去重。
- **并行数**（`ResolveWorkers`）：`requested>0` → `max(1,min(requested,jobCount))`；`requested==0` →
  `min(max(1,CPU/2), floor(空闲物理内存GB/1.2), 8, jobCount)`；内存查询失败上限按 3。`FreePhysicalGb` 用 `GlobalMemoryStatusEx`。
- **分桶**（`PlanBuckets`）：owner 按 `Weight` 降序（相等按原下标）稳定排序，逐个放进当前负载最小的桶
  （相等取靠前桶）；负载累加 `max(1,Weight)`；每桶一个后台线程、一个 Blender 进程。
- **看门狗**（`ResolveTimeoutMs`）：`base=max(60s, TaskTimeoutMinutes*60s)`（默认 20 分钟）+
  `min(100min, floor(size/10MB)*5min)`，`size=Weight>0?Weight:源文件字节数`；是**空闲超时**：
  距上一条 `BEGIN/RESULT/JOBS=` 超过该时长才判超时；200ms 轮询。
- **进程启动**：参数逐字
  `--background --factory-startup --python-exit-code 2 --python "<脚本>" -- "<task.json>"`；
  `--python-exit-code` 必须在 `--python` 之前（脚本未捕获异常 → 退出码 2）；stdout/stderr UTF-8；
  `CreateNoWindow`；启动后 `JobObject.Assign`（失败只警告）；登记到 `LiveProcs`。
- **任务文件**：`%TEMP%\L4D2LOD远景工坊\run\tasks_<guid>.json`（UTF-8 无 BOM）；同目录旁路 `<task>.jsonl`；
  `WriteTaskFile` 格式逐字：`{\r\n`、` "quality": true,\r\n`、` "jobs": [\r\n`、每行两空格缩进
  `{"src": "...", "dst": "...", "ratio": r, "shrinkInner": s, "minFaces": n, "guardPct": g[, "quality": bool]}`，
  字段序固定；`ratio/shrinkInner` 用 `0.########`、`guardPct` 用 `0.####`，InvariantCulture；`quality` 覆盖只在有值时写。
- **stdout 协议**（逐行、UTF-8、flush）：`JOBS=<n> QUALITY=<True|False> BLENDER=<version>`、`BEGIN <i>`、
  `RESULT {json}`、`OK/FAIL/WARN/DONE`。C# 侧 `JOBS=` 置 `SawStart`，`BEGIN` 记录当前任务，
  `RESULT` 解析 `idx/src/dst/ok/before/after/target/blocks/applied/warn/error`（按 `idx`→`dst`→`src` 匹配到全局下标）；
  未带 idx 时按 dst/src 兜底；重复结果忽略。
- **jsonl 兜底**：进程退出/被杀后读 `<task>.jsonl`，把没登记过的结果补齐（每任务只登记一次），随后删除任务文件与 jsonl。
- **崩溃/超时续跑**：每次 `RunProcess` 后，未拿到结果的任务留下继续；
  若 `!SawStart && !TimedOut` → 视为"脚本没跑起来"，剩余任务全部失败（重试无意义）；
  否则只失败"肇事任务"（当前 BEGIN 的任务；没有则最靠前的 pending），其余任务**换新进程继续**（每轮至少消掉一个，必然收敛）。
- **取消/KillAll**：`KillAll()` 递增 `_killEpoch` 并立即 Kill 所有 `LiveProcs`，随后按总预算最多等 1.5s（不逐个等，避免 UI 线程被拖住）；
  运行中 `RunContext.Stopped = cancel.IsCancellationRequested || 当前 epoch != 启动时 epoch`；
  停止后不再启动新进程，未完成任务标「已取消」；`LiveProcessCount` 供自测/诊断。
- **Job Object**：每个 Blender 进程 Assign 进 `JobObject`（KILL_ON_JOB_CLOSE），主程序被结束也不留孤儿；
  调度器自身还提供 `TrackProcess/UntrackProcess` 供 `BlenderLocator.ProbeVersion` 复用。
- 前置检查：Blender path 缺失时尝试 `BlenderLocator.Find`；脚本释放失败/找不到 Blender/已取消 → 所有 owner 直接失败
  （错误分别为「找不到 Blender」「无法释放后端脚本: …」「已取消」）。
- 临时残留：每进程一次清理 `run\tasks_*` 中超过 6 小时的文件。
- 诊断：失败时尾部输出取最后 60 行（`TailMaxLines`），从中找含 Error/Exception/FAIL/EXCEPTION_ 的最后一行为用户原因。

### 5.5 后端脚本 `src/Assets/blender_backend.py`（736 行）

- 启动：`blender.exe --background --factory-startup --python-exit-code 2 --python <脚本> -- <task.json>`；
  `sys.stdout/stderr reconfigure(encoding='utf-8', errors='replace')`（GBK 控制台打中文不崩）。
- 常量：`DEFAULT_MIN_FACES=12`、`DEFAULT_GUARD_PCT=35.0`、`WARN_OVER=1.5`、`AUTO_SMOOTH_DEG=60`；
  `_IS_41_PLUS = bpy.app.version >= (4,1,0)`（4.1 移除了 `mesh.use_auto_smooth`）。
- **辅助集合过滤**：`_helper_collection_names()` 收集名字以 `glTF_not_exported` 开头的集合（glTF 导入器为骨骼显示生成的
  Icosphere 等），`scene_mesh_objects()` 跳过这些集合里的 MESH，避免多算/多处理。
- **任务参数**：`job_value(job,key,default,conv)` 显式判 `None`（0 是合法值，不能被 `or 默认值` 吞掉）；
  `quality` 可 job 级覆盖整批。
- **每任务流程**：
  1. `bpy.ops.wm.read_factory_settings(use_empty=True)` → `import_gltf(src)`：
     `import_scene.gltf(filepath=src, merge_vertices=True)`，老版本 `TypeError` 退化为不带该参数；
  2. `scene_mesh_objects()`；无网格/面数 0 → RuntimeError；
  3. 全局包围盒对角线取最大，`shrink_dist = diag * shrink_inner`；
  4. 每个网格对象 `decimate_object`：
     - `prepare_mesh`：多用户网格 `data.copy()`；`shape_key_clear()`；`weld_by_position`（bmesh `remove_doubles`，
       阈值 `max(diag*1e-6,1e-8)`，解决"平直着色断点造成假连通块/Decimate 裂缝"）；有自定义法线则
       `clear_custom_normals_and_smooth`（清 split normals → 全平滑 → 按 60°：4.0 用 `use_auto_smooth/auto_smooth_angle`；
       4.1+ 先 `shade_smooth_by_angle`，失败退 `shade_auto_smooth`，再失败手工按夹角标硬边）；
     - 质量模式：`analyze_blocks`（bmesh 并查集按面连通块）→ `allocate(sizes,ratio,min_faces,guard_pct)`：
       每块先按比例、再保底 `min_faces`，保底总额不超过预算的 `guard_pct%`，仍超预算从大块逐个扣 1（不扣到保底线）；
       `separate(type='LOOSE')`（按 separate 前对象集合识别零件）→ 每块 `Decimate(COLLAPSE, triangulate)` → `join` 回原对象，
       保留原名/数据块/修改器/父子；`need_work==0` 或单块时直接全局 Decimate；
     - 速度模式：纯全局比例，不分析连通块；
  5. 内缩：对象名含 `body`（`is_inner_wrapped`）且面数>0 → 沿顶点法线内缩 `shrink_dist / 世界平均缩放`；
  6. `export_glb`：`export_format='GLB', use_selection=False, export_apply=False`，导出后校验存在且 ≥20 字节；
  7. 结果 `rec`：`idx/src/dst/ok/before/after/target/blocks/applied/warn/error/seconds`；`target_total>0 && after>target*1.5`
     → `warn` 说明（"实际面数超出目标…因小块差值<2 未简化"）；
  8. `emit_result`：先把同一 JSON 追加到 `<task>.jsonl`（flush + fsync），再 `print("RESULT "+json, flush=True)`；
     人类可读行 `OK/FAIL`、`WARN`、收尾 `DONE ok=<n> fail=<m> 用时<X.X>s`。
- 测试钩子（只给自动化用）：`L4D2LOD_TEST_CRASH` 子串命中源路径 → `os.abort()` 模拟原生崩溃；
  `L4D2LOD_TEST_SLEEP=<秒>` 且源路径含 `sleepme` → 卡住指定秒数（验证看门狗）。

## 6. 模型编解码（`src/Engine/Model/**`）

### 6.1 数据模型（`ModelContracts.cs`）

`SmdBone{Index,Name,Parent}`；`SmdWeight{BoneIndex,Weight}`；
`SmdVertex{Bone,X,Y,Z,Nx,Ny,Nz,U,V,Weights}`（`Bone` 是顶点行第一个字段=主骨骼索引；写出时若 Weights 非空用第一个权重的骨骼）；
`SmdTriangle{Material,V0,V1,V2}`；
`SmdModel{SourcePath,Bones,Triangles,Warnings,SkeletonPose}` + `TriangleCount/HasSkinWeights`。
`GlbNode{Name,Mesh?,Skin?,Children,Matrix/Translation/Rotation/Scale}`；`GlbSkin{Name,Joints,InverseBindMatrices}`；
`GlbPrimitive{MaterialName,Positions,Normals,Uvs,Indices,Joints,Weights}`；`GlbMesh{Name,Primitives}`；
`GlbModel{SourcePath,Meshes,Nodes,Skins,Warnings}`。

### 6.2 SMD 读写（`SmdCodec.cs`）

- 读取：`Parse(path)` → `ReadAllBytesShared` → `ParseBytes`；文件不存在/为空/无 `triangles` 段抛 `InvalidDataException`（中文）；
  编码：BOM 优先（UTF-8/UTF-16LE/BE），无 BOM 先严格 UTF-8，失败退 GBK(936)，再失败按 UTF-8 替换；
- 段解析：`version`、`nodes`、`skeleton`、`triangles`；容忍 CRLF/LF、空行、`//` 注释、缺 links 数量、links 声明多于实际、
  段落缺 `end` 时遇到下一段头自动恢复；坏行跳过并写 `Warnings`（带行号，最多 120 条，超出补"警告过多"）；
- `nodes`：`索引 "名称" 父索引`；索引重复/重名/空名给警告；`skeleton` 保存原始 6 数字姿态行（`SkeletonPose`），
  行数不是骨骼数整数倍给警告；
- `triangles`：先收集段内非空/非注释行，再按"材质行 + 恰好 3 个顶点行"分组；顶点行格式
  `bone x y z nx ny nz u v [links [bone weight]...]`；`links` 缺失按 0；坏行跳过不整组错位；
- 写出 `Write/WriteBytes`：UTF-8 无 BOM、CRLF、InvariantCulture；首行注释 `// 远景工坊 · L4D2 自动 LOD 工具 生成`；
  `version 1`；有骨骼才写 `nodes`/`skeleton`（保留源姿态行）；`triangles` 每条材质 + 3 顶点行；
  浮点格式 `"0.000000###"`（至少 6 位小数，最多 9 位，NaN/Infinity 写 0）；顶点行**始终写 links 数量**（含 0）；
  材质空 → `material0`；骨骼名里引号/换行替换为空格；
- 坐标/单位**原样读写**，不做轴系/缩放换算（Blender 导入导出互为逆变换）。

### 6.3 GLB 读写（`GlbCodec.cs` + `GlbJson.cs`）

读取支持范围：GLB 容器（JSON chunk + BIN chunk）、`bufferViews/accessors`（`byteOffset`、`byteStride`、`componentType`、
`normalized`、min/max）、属性 `POSITION/NORMAL/TEXCOORD_0/indices/JOINTS_0/WEIGHTS_0`、`nodes`（层级 + TRS/matrix，
matrix 4x4 列主序）、`skins`（joints + 可选 IBM）、材质名。几何/UV 原样，不做坐标换算。
明确拒绝项（抛中文 `InvalidDataException`）：非 glTF 2.0（`asset.version` 不是 2.x）、
`KHR_draco_mesh_compression`、`KHR_mesh_quantization`、sparse accessor、外部 buffer、非三角图元（mode≠4）、
索引数不是 3 的倍数、索引越界、缺少 POSITION/attributes、文件截断/文件过小/非 GLB 魔数/版本 1、JSON 段非法等。
`Read`/`ReadBytes` 不静默容错：坏文件给可读错误；`CountTriangles(path)` 只读索引统计。

写出 `WriteFromSmd(model)`：单 mesh、按材质分 primitive、三角 soup；POSITION（含 min/max）、NORMAL、TEXCOORD_0、indices、
`JOINTS_0`（ushort）、`WEIGHTS_0`（float，归一化）；骨骼节点树（节点名=SMD 骨骼名，父子按 `SmdBone.Parent`）、
skin（joints + 单位 IBM）；BIN chunk 4 字节对齐；**写出后立即自校验**（读回三角面数必须一致，否则抛）；
`Generator="Farsight LOD Studio"`、mesh 节点名 `LODMesh`；SMD 无三角形/有权重但无骨骼 → 拒绝生成 GLB。

### 6.4 SMD→GLB→SMD 与骨骼映射（`SmdGlbCodec.cs`）

- `SmdToGlb(model)` = `GlbCodec.WriteFromSmd`（Blender 只吃 GLB）。
- `GlbToSmd(glb, original)`：输出 SMD 的 `nodes` 段**完全来自原始 SMD**（与 Blender 输出无关，`original==null` 时为空表并警告）；
  逐 mesh/primitive/三角形生成 `SmdTriangle`；几何/UV 直接取 GLB 属性；
- 权重还原链：`JOINTS_0` 值 → `skin.joints[值]` → node 下标 → node 名 → 原始 SMD 同名骨骼 `Index`（大小写不敏感）；
  - skin 选择：优先找引用该 mesh 的 node 的 `node.skin`；没有则仅当只有 1 个 skin 时使用，否则按静态网格处理并警告；
  - 重名骨骼 Blender 加的 `.001/.002` 后缀：去掉末尾 3 位数字再匹配一次并计数；
  - 找不到的骨骼名 → 回落骨骼 0（保留权重）+ 警告；超过 4 个影响 → 按权重降序截断并重新归一化；
  - `JOINTS_0/WEIGHTS_0` 不完整 → 权重丢失（静态网格）+ 警告；
  - 无权重顶点 → 按无骨骼顶点写出；
  - 材质缺失 → `material0`；
  - 已知局限：多 skin 且无节点关联时按静态网格处理；所有警告写入 `SmdModel.Warnings` 并进日志/报告。

## 12. 不变量与安全红线（改代码前必读）

1. **原子写**：QC 文本一律 `FileUtil.WriteAtomic`；失败时原文件必须仍在（原位或 `.old_*`）。
2. **备份失败即中止**：任何一个待写文件的备份失败 → 整个 QC 一个字节都不改；备份名 `.lodbak` 永不覆盖。
3. **缺结束标记拒改**：`ToolBlockBroken` / `CommentOutForeignLod` 返回 -1 时禁止写该 QC，给 `BrokenBlockMessage`。
4. **绝不删除唯一副本**：任何失败路径都不允许出现"原文件已删、新文件未写成"。
5. **幂等**：重复运行不叠加工具块、内容不变不写盘不备份；文件编码/BOM/换行沿用原文件。
6. **InvariantCulture**：QC `$lod` 数字、SMD 浮点、任务 JSON、INI、报告数字全部用小数点（de-DE 等区域下也不能变逗号）。
7. **取消后不改 QC**：取消/停止只影响未完成工作；已生成 LOD 保留；取消后不再开始新的 QC 修改（已处理完的 QC 保留结果）。
8. **主模型不丢**：默认 `$model` 也生成 LOD；只有显式开「跳过主模型」且清单命中才跳过。
9. **`innode` 不处理**、`$shadowlod` 不生成、`fallback` 只提示不处理、非 glb/smd 不动。
10. **不覆盖用户的包装 QC**：`EnsureWrapperQc` 已存在即沿用。
11. **子进程无孤儿**：Blender/编译器进 Job Object；取消/关闭窗口走 `KillAll()`。
12. **Engine 不依赖 UI**：`src/Engine/**` 禁止 `System.Windows.*`/`System.Windows.Forms.*`（保证 headless）。
13. **测试不碰真实数据**：自测/E2E/UI 审计只用临时目录；`L4D2LODSTUDIO_SETTINGS_DIR` 可覆盖设置目录。
14. **不修改用户其他文件**：工具只写 `*_lodN.glb|smd`、QC/`_LOD.qc`/`_LOD合集.qc`、`.lodbak`、报告/日志/设置；不碰 `.bat`、材质、贴图、源模型。
15. **报告/日志失败不影响运行**：`ReportWriter` 逐级回退并返回 null，调用方只记警告。

## 16. 版本与维护提示

- 改动引擎公开契约（`src/Engine/**Contracts*.cs`、`QcModels.cs`、`Contracts.cs`）时同步更新本文与 `docs/01_开发约定.md`。
- 改动 `blender_backend.py` 后必须重新构建（哈希变化 → 新脚本文件；旧脚本 7 天后由 TempCleaner 清理）。
- 改动 `AppSettings` 键名会让旧设置失效（读取容错会回默认）；需要兼容时新增键而不是改名。
- 改动 QC 标记块文本会破坏"接管旧版工程"的兼容承诺（见 `docs/00 §1.4`），非必要不动。
- 文档与实现冲突时：**以代码为准**，在本文件 §14 追加一行；修复代码后再删差异行。
